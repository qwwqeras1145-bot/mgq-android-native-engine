# 手机上怎么用

本文说明怎么用这个**原生引擎**在安卓手机上运行你自己拥有的 NScripter 游戏。

> ⚠️ 本仓库不含任何游戏数据。你需要自己有游戏文件。

---

## 一、准备游戏数据

把游戏目录里的**必要文件**放到手机上。引擎需要这些：

| 文件/目录 | 必需 | 说明 |
|---|---|---|
| `nscript.dat` | ✅ | 编译后的脚本（约 10 MB）。没有它无法运行 |
| `arc*.nsa` | ✅ | 资源归档（本游戏共 3.1 GB） |
| `system/` | ✅ | 文字窗、字体、界面图（约 46 MB，散装未打包） |
| `mod/` | 可选 | 追加剧本（本游戏 17 个） |
| `save/` | 自动创建 | 存档目录 |
| `*.exe` / `*.dll` | ❌ 不需要 | 那是 Windows 用的，安卓版是原生引擎，不用它们 |

### 关键：路径必须是纯英文

```
✅ 推荐：  /sdcard/Games/mgq/
❌ 避免：  /sdcard/游戏/勇者大战魔物娘/
```

引擎内部对路径做了 `\` → `/` 归一化，也会按大小写不敏感查找，
但**归档里的文件名是 GBK 编码**，某些安卓机型的文件系统对非 ASCII 路径支持不一致。

### 空间要求

```
游戏数据（本游戏）      4.26 GB
引擎首次镜像到私有目录  约 4.3 GB（nscript.dat + *.nsa + system/）
───────────────────────────────
建议预留                9 GB 以上
```

> 引擎会把必要文件**镜像一次**到应用私有目录，之后的启动直接复用缓存。
> 之所以要镜像：`.nsa` 需要**随机访问**（arc2.nsa 有 1.7 GB，要按偏移读取），
> 而安卓的 SAF 接口只提供流、不能 seek。

## 二、安装与运行

### 1. 构建 APK

```bash
# 需要 Android SDK（platform 34 + build-tools 34.0.0）和 JDK 17+
echo "sdk.dir=/你的/android-sdk/路径" > local.properties
./gradlew :android:assembleDebug
```

产物：

```
android/build/outputs/apk/debug/android-debug.apk     （实测 3.18 MB）
```

> 为什么只有 3 MB？因为**不含游戏数据**。游戏由你提供。

### 2. 装到手机

```bash
adb install -r android/build/outputs/apk/debug/android-debug.apk
```

或直接把 APK 拷到手机点安装（需允许「安装未知来源应用」）。

### 3. 把游戏数据放进手机

```bash
# 例：推到内置存储的 Games/mgq
adb shell mkdir -p /sdcard/Games/mgq
adb push D:\mgq/nscript.dat /sdcard/Games/mgq/
adb push D:\mgq/arc.nsa     /sdcard/Games/mgq/
adb push D:\mgq/arc1.nsa    /sdcard/Games/mgq/
adb push D:\mgq/arc2.nsa    /sdcard/Games/mgq/
adb push D:\mgq/arc3.nsa    /sdcard/Games/mgq/
adb push D:\mgq/arc4.nsa    /sdcard/Games/mgq/
adb push D:\mgq/system      /sdcard/Games/mgq/
```

> 4.3 GB，用数据线推比较稳。中途断了重跑即可。

### 4. 在手机上操作

1. 打开 **MGQ 原生引擎**
2. 点「选择游戏目录」
3. 在系统文件选择器里定位到 `Games/mgq`，点「使用此文件夹」
4. 允许读取权限

首次启动会镜像数据（4 GB 左右，几分钟），之后秒开。

## 三、当前能玩到什么程度

**必须先说清楚**：这是引擎实现，**不是成品游戏**。

| 功能 | 状态 |
|---|---|
| 脚本解析（441,712 条指令） | ✅ 全部识别 |
| 目录选择、数据镜像 | ✅ 已实现 |
| 背景/立绘绘制（`bg` / `lsp`） | ✅ 已实现 |
| 伪 3D 精灵（`lsp2` / `msp2` / `amsp`） | ✅ 已实现（含中心坐标、逆时针旋转） |
| 文字显示与换行 | ⚠️ 基础实现，CJK 排版需打磨 |
| BGM / 音效 / 语音（ogg） | ✅ MediaPlayer |
| 存档（`save` / `load`） | ⚠️ 引擎侧已实现，未与游戏自带存档菜单对接 |
| **特效（288 处 x86 DLL 调用）** | ❌ **未实现**，会跳过 |
| **视频（19 处 `mpegplay`）** | ❌ **未实现** |

### 为什么会缺特效

游戏有 288 处 `print` 调用会去加载 **x86 的 Windows DLL**：

```
breakup.dll   画面碎裂效果   (203 处)
lngtwave.dll  水波纹效果      (73 处)
trvswave.dll  字形变换        (11 处)
NSFont.dll    字体扩展         (1 处)
```

这些是 32 位 x86 原生代码，**安卓无法加载**——
这正是「原生重写」和「模拟器」的分界线：
模拟器能把 x86 指令翻译过来跑，原生实现必须用 Kotlin 重新写一遍这些效果。

目前这些调用会被记录并跳过：**不会崩，但相应画面效果缺失**。

## 四、出问题怎么查

### 应用闪退 / 黑屏

用 `adb logcat` 看引擎日志，日志 tag 是 `mgq`：

```bash
adb logcat -s mgq:V AndroidRuntime:E
```

### 提示「所选目录里没有 nscript.dat」

说明选错层级了。要选**包含 `nscript.dat` 的那一层**，
不是它的上一级，也不是 `system` 子目录。

### 图片/音乐加载不出来

在电脑上先跑一次归档检查，确认资源确实存在：

```bash
./gradlew :core:run --args="nsa D:\mgq\arc4.nsa"
```

输出会列出发现的载荷对象数、首个对象的偏移和魔数。
若 `names` 是 `partial`，说明部分文件名没能从索引恢复——
这是已知限制（见 [README](../README.md#nsa-归档为什么用签名扫描而不是解析索引)），
数据本身仍可读取，只是按名字查找会失败。

### 想确认脚本解析没问题

```bash
./gradlew :core:run --args="dump <解码后的脚本.txt>"
```

正常应输出：`instructions : 441712`、`UNKNOWN 指令 : none`、
`parser 问题 : 6`（那 6 处是脚本原文的笔误，不是引擎问题）。
