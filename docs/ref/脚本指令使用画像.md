# 脚本指令使用画像（勇者大战魔物娘 / Monster Girl Quest）

> 面向 Kotlin/Android 原生 NScripter 引擎重实现的侦察报告。
> 所有数字均由脚本逐行扫描计算得出，非估计值。

- **分析对象**：`D:\deep工作区\recon\result.txt`
- **来源**：`nscript.dat`（9,736,822 字节）经 NSDEC Ver.0.7 反编译后的明文脚本
- **编码**：GBK / CP936（严格解码通过，零替换字符）
- **换行**：CRLF（382,324 个），无孤立 LF/CR
- **规模**：10,119,146 字节，**382,325 行**
- **机器可读结果**：`D:\deep工作区\recon\command_inventory.json`

| 项目 | 数值 |

| 物理行数 | 382,325 |
| 指令调用总数 | 311,935 |
| **不同指令数** | **163** |
| ① 游戏自定义宏（defsub） | 16 |
| ② 参考内置指令集内 | 68 |
| ③ **不在参考内置集内（未知/扩展）** | **79** |
| 纯文本/操作数行（`<no-cmd>`） | 99,291 |
| 标签总数 | 9,771（与预期一致） |
| 标签：被 goto/gosub 到达 / 从未被引用 | 6,760 / 1,563 |
| Lua 引用 | **0** |
| 资源引用 | 30,732 次 / 7,247 个不同资源 |
| 断链 goto/gosub 目标 | **15 个**（另有 1 个动态前缀 + 4 个标签命名缺陷） |

**给移植工作的三条硬结论：**

1. **`name` 覆盖了同名内建指令**（`defsub name`），且出现 66,711 次 —— 它是全脚本调用最多的指令。移植时必须支持「宏覆盖内建指令名」，并如实实现该宏的语义（见 §A.3、§J）。
2. **`print` 有两种完全不同的语义**，靠参数个数区分：`print 1` = 立即重绘刷新；`print x,y` = 文本推进并等待点击（第二参为超时毫秒）。另有 `print x,y,"system\xxx.dll/yyy"` 调用 Win32 特效 DLL（288 次，5 个不同 DLL）—— 这些 DLL 在 Android 上无法加载，必须原生重写（见 §G）。
3. **控制流有一个易错歧义**：`if <条件>` 单独成句时是「块头」，其条件会成为新的当前状态并一直持续到下一个 `if` 行；`if <条件> <指令>` 才是单指令条件。全脚本有 70 处块头形式（见 §A.4）。

## A. 指令清单

### A.1 解析规则（必须处理的所有形态）

本报告使用的分词规则，均已在本脚本中验证存在：

| 形态 | 处理方式 | 本脚本中的出现量 |
|---|---|---|
| CRLF | 按 `\r\n` 切行 | 382,324 个 |
| 注释 `;` | `;` 起至行尾为注释，**但引号内的 `;` 不是注释** | 1,115 行为纯注释行 |
| 行首空白 | 前导 TAB/空格是反编译产物，无语义（见下） | 3,290 行前导空白 |
| 链式 `:` | 一行内用 `:` 串联多条指令（**引号内 `:` 不算**） | **32,464 行**含真实链式；`:` 字符共 64,965 个，其中仅 5 个在引号内 |
| TAB 分隔 | TAB 既作缩进、也作链式分隔符 | 3,992 行含行内 TAB（其中 3,904 行同时是链式行） |
| 标签 | `*name` 定义标签 | 9,771 行 |
| `if ... :` | 条件后接链式指令 | 见 §A.4 |
| `notif` | `notif <条件> <指令>`＝取反 if，语法同 if | 69 次 |
| 参数紧贴 | **命令名后可紧跟引号/括号/逗号，无空格**：`bgm"bgm\irias.ogg"` | `bgm` 1,515 次、`bgmonce` 等 |
| 文本行 | 首 token 不是 ASCII 标识符 → 文本/对白输出语句 | 99,291 行 |

> **前导 TAB 无语义的证据**：`*credit` 标签之后（L67096 起）整段宏体每行都带一个 TAB，而脚本其余部分不带。同一脚本中两种风格并存，说明 TAB 只是反编译器的排版痕迹。另有 `mov %creditnow,%creditnow+1\t: mov %credity,%credity+50`（L67111）证明 TAB 也可作行内链式分隔符。

### A.3 最重要的发现：`name` 覆盖内建指令

```nscripter
; L308506
defsub name
```
```
; L297506  *name 标签本体
getparam $platename
if $platename="" csp 599:print 1:return
len %name_count,$platename
lsp 599,":s/20,20,0;#FFFFFF"+$platename,155-%name_count*5,408:print 1
return
```

- `defsub name` 把**内建指令 `name`** 注册为宏，之后所有 `name xxx` 调用都进入上面的标签。
- 调用次数 **66,711**（全脚本第一），其中 66,704 次是行首出现。
- 参数形态：**永远 1 个参数**（66,703 次内联参数 + 1 次链式）。参数可以是字符串常量 `"伊莉娅丝"`，也可以是字符串变量 `$name`（9,265 次）。
- 该宏本身说明：`name` 是**状态设置器**（绘制姓名条），不是对白输出指令。对白由那 9 万余行「无指令行」输出。
- **移植要求**：宏/`defsub` 机制必须允许覆盖内建指令名；指令查找顺序为「先查宏表、后查内建表」。

脚本中 `name` 后一行的分布也印证了它是状态设置器而非两行式指令：

| `name` 行之后是什么 | 次数 |
|---|---:|
| 文本行（对白） | 42,416 |
| 另一个 `name` 行 | 10,813 |
| `lsp` / `gosub` / `skillname` / `goto` / `if` / `mov` 等指令 | 约 13,000 |

即 `name ""`（清除姓名条）之后紧跟下一位说话者的 `name "鲁卡"` 是常见写法；若当成「两行式指令」，这 10,813 处会成为空操作，与实际不符。

### A.4 `if` / `notif` 形态统计

| 形态 | 次数 |
|---|---:|
| `if` 调用总数 | 54,286 |
| 其中：带后续指令（`if <cond> <cmd>` 或链式） | 54,216 |
| 其中：**块头形式**（`if <cond>` 单独结束） | **70** |
| `notif` 调用总数 | 69 |
| 其中：带后续指令 | 69 |

**块头形式必须正确实现**：`if <cond>` 之后条件保持「当前状态」，直到下一个 `if` 行才被替换。实例（L92）：

```nscripter
91: if %sentaku=1 skip 91
92: if %sentaku=2
93: for %move=2201 to 2499 step 1
94: mov %%move,1
95: next
...
```
若误判为「无操作的 if」，L93 起的整个 for 块将无条件执行，剧情与存档数据都会被污染。

### G.1 「2 参数形式是否等于文本打印形式」的判定

**判定结果：`print x,y` 是「等待/推进」而非「打印文本」，两者是不同指令族。**

证据：

1. **1 参数形式 `print 1` 与文本无关**。它出现在宏体内用于强制重绘：
   ```nscripter
   *name  (L297509)
   if $platename="" csp 599:print 1:return
   ...
   lsp 599,":s/20,20,0;#FFFFFF"+$platename,155-%name_count*5,408:print 1
   ```
   `print 1` 紧跟 `lsp` 之后，语义是「把刚设好的精灵刷到屏幕」。
2. **2 参数形式第二参数是时间量**：取值 500 / 1500 / 3000 / 4500 等毫秒级常量，且总是跟在 `lsp`/`cspl`/`csp` 之后：
   ```nscripter
   L182: cspl 700,701:print 10,500
   L239: lsp 700,":a;chara\iriasu_st01.bmp",0,0:print 10,3000
   L288: lsp 700,":a;chara\iriasu_st04.bmp",0,0:print 10,1500
   ```
   这与「第一参=模式（10），第二参=超时」的 NScripter `print`（等待点击）语义一致。
3. **2 参数形式从不携带文本内容**。全脚本 12,228 个 2 参 `print` 的实参全部是数字/表达式，**没有一个是字符串**。
4. **文本输出走另外的通道**：99,291 行「无指令行」+ `name` 宏 + `csel`。这也解释了为何 `print` 虽出现 13,206 次却几乎不产生对白。
5. **3 参数形式第三参是 `"*.dll/..."`**，明确是外挂特效调用，与文本无关。

**结论**：`print` 的三种形式（重绘 / 等待点击 / DLL 特效）**都不同于「打印文本」**。移植时 `print` 需要按元数分派三个独立实现。
