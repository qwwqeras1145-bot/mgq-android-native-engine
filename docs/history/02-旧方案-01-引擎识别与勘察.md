# 01 · 引擎识别与目录勘察

移植任何游戏的第一步都不是写代码，而是**搞清楚你要对付的是什么**。
这一步做错，后面全是白费。本文记录本项目实际用到的勘察方法。

---

## 1. 为什么先看引擎

不同引擎的安卓路线完全不同，甚至"能不能"都不同：

| 引擎 | 安卓可行路线 | 难度 |
|---|---|---|
| RPG Maker MV/MZ | JoiPlay / 直接浏览器 | ⭐ 极低（本来就是 JS） |
| Ren'Py | 官方安卓打包 | ⭐ 低（有源码时） |
| KiriKiri | Kirikiroid2 | ⭐⭐ 低 |
| RPG Maker XP/VX/Ace | JoiPlay | ⭐⭐⭐ 中 |
| **NScripter** | **Winlator** | ⭐⭐⭐ 中 |
| Unity | 无（需工程源码） | ❌ 不可行 |

**看错引擎 = 方案全错。** 所以第一步永远是识别，不是动手。

---

## 2. 实地勘察的四个动作

### 动作一：列目录，看顶层结构

```powershell
Get-ChildItem -LiteralPath "D:\游戏\某游戏"
```

本项目测试目标返回：

```
d-----  bgm
d-----  effect
d-----  mod
d-----  save
d-----  se
d-----  system
d-----  魔物娘系统所用的nscripter解包封包工具
-a----  708815869  arc.nsa
-a----  882667354  arc1.nsa
-a----  1725769295 arc2.nsa
-a----  5853469    arc3.nsa
-a----  516949     arc4.nsa
-a----  3448       default.css
-a----  51         envdata
-a----  9736822    nscript.dat
-a----  53248      NSFont.dll
-a----  331776     nslua.dll
-a----  245760     nsogg2.dll
-a----  172032     nspng.dll
-a----  1095680    勇者大战魔物娘三章完全汉化版.exe
```

**立刻能读出的信息：**

1. `nscript.dat` → NScripter 引擎的编译脚本
2. 5 个 `.nsa` → NScripter 归档包，共 3.10 GB
3. `nslua.dll` → **带 Lua 扩展**，这是最关键的一条（决定 ONScripter 是否可用）
4. `nsogg2.dll` / `nspng.dll` → 自定义音频/图像解码扩展
5. `envdata` → NScripter 的运行配置
6. `.exe` 只有 1 MB → 它是**解释器**，不是游戏本体
7. 目录里居然自带 `nscripter解包封包工具`（`nsaarc.exe`/`nscdecode.exe` 等）

> 💡 **第 6 条最容易被忽略。** exe 只有 1 MB，说明游戏逻辑不存在 exe 里。
> 任何"把 exe 反编译重写"的思路在这里都是完全走错方向。

### 动作二：验 exe 是不是标准 PE

```powershell
$b = [System.IO.File]::ReadAllBytes($f)[0..1023]
($b[0..15] | ForEach-Object { $_.ToString('X2') }) -join ' '
```

```
4D 5A 90 00 03 00 00 00 04 00 00 00 FF FF 00 00
```

`4D 5A` = `MZ`，标准 DOS/PE 头。说明**没有加壳**（加壳的 exe 这段会被改写）。

同时从 ASCII 段能看到：
```
Rich....PE..L......N...........text....d....rdata...data....rsrc
```

标准 MSVC 编译产物，`text`/`rdata`/`data`/`rsrc` 段齐全 —— **无损、未加密**。

### 动作三：量体量构成

```powershell
Get-ChildItem -LiteralPath $p -Recurse -File |
  Group-Object Extension | Sort-Object Count -Descending |
  Select-Object -First 12 Count, Name
```

本项目结果：

```
Count Name
  682 .bmp
  312 .ogg
  223 .png
  168 .jpg
   44 .ini
   32 .txt
   25 .dat
    9 .exe
    8 .dll
    8 .wav
    5 .nsa
    3 .mpg
```

**读法：**

- `.bmp` 有 682 个且合计 835 MB → 大量**未压缩位图**，是体积元凶
- 但注意：这些是**解包后**的散文件，游戏实际运行时走 `.nsa` 内的副本
- `.nsa` 占 3.10 GB / 4.26 GB ≈ **73%** —— 素材是压倒性主体

### 动作四：用工具复算一遍

```bash
python tools/analyze_port.py "D:\游戏\某游戏"
```

自动完成上述全部判断，并给出路线建议。

## 3. 本项目测试目标的勘察结论

```
总体积   : 4.26 GB
文件总数 : 1,524
判定结果 : NScripter
命中证据 : file:nscript.dat, ext:.nsa, glob:nscript.*,
           contains:nslua, contains:nsfont
再分发风险: 高
```

**风险判定为"高"的依据**（`analyze_port.py` 的启发式）：

> 目录内同时存在 Windows 可执行文件与引擎归档包，
> 这是典型「商业游戏的本地安装副本」形态。

这个提示不是多余的。测试目标自带的说明文件里写着：

> 本游戏汉化仅仅为了日语学习交流 请在下载24小时内自行删除
> 如果喜欢本游戏请支持正版

**游戏自己的说明文件承认了它未经授权。** 这一条直接决定了后续所有方案的边界。

## 4. 勘察清单（可复用）

对任何游戏，按顺序回答这 7 个问题：

1. ☐ 目录里有没有**归档包**（`.nsa` / `.xp3` / `.rpa` / `.arc`）？→ 有归档 = 引擎自带资源管理
2. ☐ 主 `.exe` **多大**？→ 小于 5 MB 基本是解释器，逻辑在别处
3. ☐ 有没有**脚本/数据目录**（`Data/`、`www/`、`renpy/`）？
4. ☐ 有没有**扩展 DLL**（`nslua.dll`、`RGSS*.dll`）？→ 决定开源复刻方案是否可用
5. ☐ 归档包 vs 散文件，**谁占大头**？→ 规划手机存储
6. ☐ 有没有**厂商自带的工具**？→ 有时省掉自己写解析器的功夫
7. ☐ 有没有**授权说明**？→ 决定你能不能公开分发

第 6 条在本项目里就中了：游戏目录自带完整的 `.nsa` 解包/封包工具链。

> **教训**：我一开始花了不少时间想搞清这个 `.nsa` 的非标准索引结构，
> 后来发现游戏目录里已经躺着 `nsaarc.exe`。
> **先找现成工具，再考虑自己写解析器。**
