# 旧方案归档（已被推翻）

这里的文档来自本项目的前身，当时的结论是：

> **「NScripter 用了 `nslua.dll`，开源引擎实现不了，所以只能靠 Winlator 跑 exe。」**

**这个结论是错的，已被实测推翻。**

## 为什么错

那条结论建立在一个**从未被验证的假设**上：`nslua.dll` 被游戏逻辑使用了。

对解包后的 382,325 行脚本全文 + 原始字节流做两次独立扫描，搜索
`lua` / `nslua` / `luac` / `.lua`：

```
Lua 引用次数 = 0
```

`nslua.dll` 只是引擎发行包附带的可选扩展。战斗、图鉴、技能统计全部用
NScripter 自己的 `defsub` 宏实现，**不需要 Lua 运行时**。

所以「只能跑兼容层」变成了「可以写原生引擎」。

## 保留它们的理由

1. **审计轨迹** —— 本次移植过程记录（[07-移植过程全记录.md](../07-移植过程全记录.md)）
   里多处引用了这些旧结论，需要能看到原文。
2. **方法论仍有价值** ——
   - [引擎识别与勘察](02-旧方案-01-引擎识别与勘察.md)：从目录结构判断引擎类型的通用清单，仍然有效
   - [为什么不能重打包APK](02-旧方案-02-为什么不能重打包APK.md)：**结论仍然成立**——把游戏塞进 APK 分发是侵权
   - [Winlator 方案](02-旧方案-03-方案A-Winlator直接运行.md)：作为替代方案本身是可行的，只是不再是首选
   - [ONScripter 路线评估](02-旧方案-04-方案B-ONScripter路线评估.md)：其核心论据（缺 Lua）已被推翻

## 一个教训

> **别人写得很详细，不等于它是对的。关键假设必须自己验。**

那 6 篇文档写得很认真、很有条理，但整条推理链挂在一个没验证过的前提上。
如果直接采信，本项目就不会存在。
