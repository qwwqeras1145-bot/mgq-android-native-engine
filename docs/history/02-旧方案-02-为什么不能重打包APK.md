# 02 · 为什么不能重打包成 APK

「把 Windows 游戏转成安卓版」这句话，隐含了一个默认技术路线：

> 把游戏拆开 → 改掉 Windows 专有部分 → 用安卓工具链重新打包成 APK

**这条路对本项目测试目标不成立，而且是技术和法律同时不成立。**

本文把两个障碍讲清楚，这样你以后遇到类似需求时可以自己判断。

---

## 一、技术障碍

### 障碍 1：NScripter 没有安卓版编译器

NScripter 是**闭源商业引擎**（作者高桥直树 / Naoki Takahashi）。
它的运行模型是：

```
nscript.dat (编译后的脚本)
      ↓
NScripter.exe (闭源解释器, 处理 Win32 GDI/DirectDraw 绘制)
      ↓
*.nsa (资源归档) + 各种 *.dll (扩展)
```

**没有任何工具能把 `nscript.dat` 编译成安卓能跑的产物。**
它不是编译器型引擎（不像 Unity 有 Build Target），而是解释器型。

### 障碍 2：`nslua.dll` 把开源复刻方案堵死了

唯一的开源希望是 **ONScripter**（NScripter 的开源重实现）。
但本项目测试目标用了：

| DLL | 作用 | ONScripter 支持 |
|---|---|---|
| `nslua.dll` | Lua 脚本扩展 | ❌ 不支持 |
| `nsogg2.dll` | OGG 音频解码 | ⚠️ 部分 |
| `nspng.dll` | PNG 解码 | ⚠️ 部分 |
| `NSFont.dll` | 字体渲染 | ⚠️ 部分 |

`nslua.dll` 是关键。测试目标用它实现了：

- 战斗系统（伤害计算、怪物属性、技能）
- 图鉴系统
- 成就系统
- 反省会

**这些都是 Lua 逻辑，ONScripter 完全没有 Lua 解释器。**
即使强行跑起来，也只剩对话部分，战斗一进就崩。

### 障碍 3：需要重写，而重写不是"移植"

如果非要走这条路，实际工作量是：

1. 解析 `nscript.dat`（非公开格式，有加密/压缩）→ 自研解析器
2. 解析 5 个 `.nsa`（非标准索引，头部结构 6 字节，与公开 NSA 规范不符）
3. 反编译 Lua 逻辑，重写成 Java/Kotlin
4. 重新实现整个渲染层、存档层、音频层
5. 处理 4.26 GB 素材的重新编码与打包

这不是"移植"，这是**重写一个游戏**。工作量以人年计，且结果必然与原作有差异。

### 障碍 4：体积

4.26 GB 素材。Google Play 的 APK 上限是 100 MB（AAB 基础包 200 MB，需走 Play Asset Delivery）。
即使不上架，用户装一个 4 GB 的 APK 也是灾难。

## 二、法律障碍

这一条比技术障碍更硬，因为它**没有技术上的绕过方式**。

### 测试目标本身的授权状态

游戏目录内的说明文件原文：

> 1 勇者大战魔物娘为暗黑特洛伊大大汉化，勇者魔物娘吧和SS同盟辅助汉化补全，至今尚未完成完全汉化版本。
> 5 本游戏汉化仅仅为了日语学习交流 请在下载24小时内自行删除 如果喜欢本游戏请支持正版。

**逐句解读：**

| 表述 | 含义 |
|---|---|
| "为暗黑特洛伊大大汉化" | 粉丝个人翻译，非官方 |
| "请在下载24小时内自行删除" | 承认这是**未经授权的复制**（正版软件不会要求你删掉） |
| "如果喜欢本游戏请支持正版" | 承认它**不是**正版 |

原文游戏《勇者大战魔物娘》（もんむす・くえすと）是日本 **Torotoro Resistance** 的商业作品，
在 DLsite 等平台正式销售。

### 汉化补丁的法律地位

这里有个常见误解需要澄清：

> "我只是做个汉化补丁，不算侵权吧？"

**汉化补丁的法律地位因法域而异，但"整合版"一定越界：**

| 形态 | 通常的法律评价 |
|---|---|
| 纯文本翻译补丁（不含游戏本体） | 各地不一，日本曾有多起刑事案例 |
| **整合版**（游戏本体 + 汉化） | **明确侵权**：这是复制 + 发行 + 演绎 |
| 上架应用商店 | 加重情节 |

**测试目标正是"整合版"** —— 4.26 GB 里包含完整的游戏本体资源（`.nsa`）。

### 上传到 GitHub 意味着什么

GitHub 的《Acceptable Use Policies》明确禁止：

> 将 GitHub 用于侵犯他人知识产权的内容分发

以及 DMCA 流程。实际后果：

1. **仓库会被 DMCA 下架**，不需要事先通知
2. **账号会被标记**，重复侵权会导致封号
3. 对于 4 GB 的仓库，GitHub 会直接判定为滥用（存储配额）
4. 权利人可主张**法定赔偿**，日本、美国、中国都有先例

### 还有一个容易被忽略的点：凭据

推送需要 GitHub Token。如果 Token 被写进仓库、脚本、CI 配置或提交历史，
**它就成了公开信息**。带 `repo` + `delete_repo` 权限的 Token 泄露，
相当于账号被接管（能删光你所有仓库）。

> 正确做法：Token 只通过环境变量或凭据管理器传入，**绝不落盘到仓库**。
> 本项目的所有脚本都不接收、不存储、不记录任何凭据。

## 三、结论

| 需求 | 可行？ | 正确做法 |
|---|---|---|
| 在**自己的手机**上玩这个游戏 | ✅ 可以 | Winlator 跑原 exe |
| 把游戏**重新打包**成 APK 自用 | ⚠️ 技术上做不到 | 无需打包 |
| 把 APK **上传**到 GitHub | ❌ 不可以 | — |
| 把游戏本体传到**任何公开仓库** | ❌ 不可以 | — |
| 写文档记录**移植过程与技术分析** | ✅ 可以 | 就是本仓库 |

**核心区分：**

> **"让软件在我自己的设备上运行"** 和 **"把软件复制给别人"** 是两件完全不同的事。
> 前者是使用，后者是发行。
>
> Winlator 方案属于前者，完全合法。
> 重打包上传属于后者，是侵权。
